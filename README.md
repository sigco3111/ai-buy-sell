## 1. 소개

**AI Buy&Sell**은 사용자가 입력한 한국 또는 미국 주식/ETF의 티커 또는 종목명에 대해 AI 기반으로 매수/매도 결정을 대신 내려주는 웹 애플리케이션입니다. AI는 Google Gemini API를 활용하여 투자 분석 및 추천을 생성하며, 시장 변동성 지수 정보와 함께 AI가 참고한 자료(Google 검색 결과)를 제공합니다. 또한, 과거 데이터를 기반으로 AI의 일일 거래 신호에 따른 투자 시뮬레이션 기능을 제공하여 사용자가 AI의 투자 전략 성과를 가늠해볼 수 있도록 합니다.

(애플리케이션 설명은 `metadata.json` 파일 참조: "Get AI-powered buy/sell/hold recommendations for Korean and US stocks/ETFs based on user input.")

**👉 라이브 데모**: [https://sigco3111.github.io/ai-buy-sell/](https://sigco3111.github.io/ai-buy-sell/) — 브라우저에서 바로 실행

## 2. 주요 기능

*   **AI 기반 주식/ETF 추천**: 특정 종목에 대한 '매수' 또는 '매도' 투자 의견 제공.
*   **다국가 시장 지원**: 한국(KOSPI, KOSDAQ) 및 미국(NASDAQ, NYSE 등) 시장 종목 분석.
*   **상세 분석 근거**: AI가 추천을 내린 이유에 대한 포괄적인 설명 제공.
*   **시장 변동성 지수**: 분석된 종목의 시장에 따라 VKOSPI 또는 VIX 지수 정보 및 현재 상태 분석 제공.
*   **참고 자료 출처**: AI가 분석에 사용한 Google 검색 기반 자료 출처(URI 및 제목) 목록 제공.
*   **거래 시뮬레이션**:
    *   과거 데이터를 기반으로 AI의 일일 거래 신호(매수/매도)를 따르는 가상 거래 시뮬레이션.
    *   사용자가 시뮬레이션 기간 선택 가능 (7일, 14일, 30일).
    *   시뮬레이션 결과 표시: 시작/최종 자본, 수익/손실(금액 및 비율), 총 거래 횟수.
    *   일일 상세 로그: 날짜별 시가/종가, AI 신호, 당일 행동, 포지션, 보유 수량, 일일 평가액.
*   **시각화**:
    *   시뮬레이션 기간 동안의 주가 변동 및 AI 거래 지점(매수/매도)을 차트로 시각화 (Chart.js 사용).
*   **API 키 관리**:
    *   사용자가 직접 Gemini API 키를 입력하고 브라우저의 로컬 스토리지에 저장.
    *   API 키의 현재 활성화 상태(누락, 로드됨, 유효, 유효하지 않음) UI 표시.

## 3. 작동 방식

1.  **API 키 입력**: 사용자는 애플리케이션 내 UI를 통해 자신의 Gemini API 키를 입력하고 로컬 스토리지에 저장합니다. 애플리케이션은 로컬 스토리지 키를 우선 사용하며, 없을 경우 `process.env.API_KEY` 환경 변수(설정된 경우)를 사용하려고 시도합니다.
2.  **종목 입력**: 사용자가 분석하고자 하는 주식 또는 ETF의 티커(예: `005930`, `AAPL`) 또는 종목명(예: `삼성전자`)을 입력합니다.
3.  **AI 추천 요청**: 애플리케이션은 입력된 종목 정보와 API 키를 사용하여 Google Gemini API(`gemini-2.5-flash` 모델)에 다음 정보들을 요청합니다:
    *   투자 의견 ('매수' 또는 '매도')
    *   분석 근거
    *   인식된 종목명, 티커, 시장 정보
    *   관련 시장 변동성 지수 (VKOSPI 또는 VIX) 정보
    *   AI가 참고한 Google 검색 자료
4.  **결과 표시**: AI로부터 받은 응답을 가공하여 사용자에게 추천 카드, 변동성 정보 카드 형태로 표시합니다.
5.  **시뮬레이션 실행 (선택 사항)**:
    *   사용자가 특정 기간(7, 14, 30일)을 선택하여 시뮬레이션을 요청합니다.
    *   애플리케이션은 해당 종목의 과거 주식 데이터를 가져옵니다 (현재는 **모의(mocked) 데이터** 사용).
    *   선택된 시뮬레이션 기간 내 각 거래일에 대해, 애플리케이션은 다시 Gemini API를 호출하여 해당일의 AI 거래 신호('매수' 또는 '매도')를 받습니다. 이 과정에서 지연(delay)을 두어 API 요청 빈도를 조절합니다.
    *   수신된 일일 신호와 과거 데이터를 바탕으로 가상 거래를 시뮬레이션합니다. (예: 매수 신호 시 시가에 매수, 매도 신호 시 시가에 매도).
    *   시뮬레이션이 완료되면, 총 수익률, 거래 내역, 일일 상세 로그 및 주가/거래 지점 차트를 사용자에게 보여줍니다.

## 4. 기술 스택

*   **프론트엔드**:
    *   React 19 (via esm.sh)
    *   TypeScript
    *   Tailwind CSS (via CDN)
*   **AI**:
    *   Google Gemini API (`gemini-2.5-flash` 모델)
    *   `@google/genai` SDK (via esm.sh)
*   **차트**:
    *   Chart.js (via CDN/esm.sh)
*   **과거 데이터**:
    *   현재 모의(mocked) 데이터 생성 로직 사용 (`services/yahooFinanceService.ts`). (향후 실제 금융 API 연동 가능)
*   **실행 환경**:
    *   모든 로직은 클라이언트 사이드 브라우저에서 실행됩니다.
    *   별도의 빌드 과정 없이 `index.html` 파일을 직접 열어 사용합니다.

## 5. 프로젝트 설정 및 실행

### 사전 준비물

*   최신 버전의 웹 브라우저 (Chrome, Edge, Firefox 등)
*   Google Gemini API 키: [Google AI Studio](https://aistudio.google.com/app/apikey) 에서 발급받을 수 있습니다.

### API 키 설정

애플리케이션은 Gemini API를 사용하기 위해 API 키가 필요합니다. 키를 제공하는 두 가지 방법이 있습니다:

1.  **인앱 UI 사용 (권장)**:
    *   애플리케이션을 실행하면 "Gemini API 키 관리" 섹션이 표시됩니다.
    *   여기에 자신의 Gemini API 키를 입력하고 "저장" 버튼을 클릭합니다.
    *   키는 브라우저의 로컬 스토리지에 안전하게 저장되어 다음 방문 시에도 유지됩니다. (다른 브라우저나 시크릿 모드에서는 재입력 필요)
2.  **환경 변수 (대체 옵션)**:
    *   만약 로컬 스토리지에 저장된 키가 없고, 이 애플리케이션을 로컬 개발 환경(Node.js 환경 등)에서 특정 방식으로 실행하여 `process.env.API_KEY` 값을 주입할 수 있다면, 해당 값을 사용합니다.
    *   일반적으로 `index.html`을 직접 여는 방식에서는 이 방법이 직접적으로 동작하지 않으므로, **인앱 UI를 통한 키 입력이 주된 방법**입니다.

### 애플리케이션 실행

1.  프로젝트 파일을 다운로드하거나 복제합니다.
2.  별도의 빌드 과정이나 서버 실행 없이, 프로젝트 루트 디렉토리에 있는 `index.html` 파일을 웹 브라우저에서 직접 엽니다.
    ```
    # 예시 (운영체제 파일 탐색기에서 더블클릭 또는 브라우저 주소창에 파일 경로 입력)
    file:///path/to/your/project/index.html
    ```
3.  화면에 "AI Buy&Sell" 애플리케이션이 로드되면, 안내에 따라 API 키를 설정하고 사용합니다.

## 6. 주요 컴포넌트 및 모듈

*   **`App.tsx`**:
    *   애플리케이션의 메인 컨테이너 컴포넌트입니다.
    *   전체 상태 관리 (입력 쿼리, API 키, 로딩 상태, 오류, 분석 결과, 시뮬레이션 데이터 등)를 담당합니다.
    *   API 서비스 함수들을 호출하고, 그 결과를 하위 컴포넌트에 전달합니다.
    *   API 키 관리 UI 및 로직을 포함합니다.
*   **`services/geminiService.ts`**:
    *   Google Gemini API와의 모든 통신을 담당합니다.
    *   `getStockRecommendation`: 주식/ETF에 대한 종합적인 투자 의견 및 관련 정보(변동성, 참고자료)를 요청합니다.
    *   `getDailyStockSignal`: 특정 날짜의 주식/ETF에 대한 일일 거래 신호(매수/매도)를 요청합니다.
    *   API 요청 시 재시도 로직 및 오류 처리 포함.
*   **`services/yahooFinanceService.ts`**:
    *   주식의 과거 시계열 데이터(날짜, 시가, 종가)를 제공합니다.
    *   **현재 이 서비스는 실제 API를 호출하지 않고 모의(mocked) 데이터를 생성하여 반환합니다.**
*   **`components/` 디렉토리**:
    *   **`InputForm.tsx`**: 사용자가 주식 티커/종목명을 입력하고 분석을 제출하는 폼.
    *   **`RecommendationCard.tsx`**: AI의 종합 투자 의견, 분석 근거, 종목 정보 등을 표시하는 카드.
    *   **`VolatilityCard.tsx`**: 시장 변동성 지수(VKOSPI/VIX) 정보와 분석을 표시하는 카드.
    *   **`SimulationResultCard.tsx`**: 거래 시뮬레이션 결과(수익률, 차트, 일일 로그 등)를 표시하는 카드.
    *   **`ErrorMessage.tsx`**: 오류 발생 시 사용자에게 메시지를 보여주는 컴포넌트.
    *   **`Modal.tsx`**: 상세 분석 근거 등을 보여주기 위한 모달창 컴포넌트.
*   **`constants.tsx`**:
    *   애플리케이션 전반에서 사용되는 SVG 아이콘 컴포넌트들(예: `ArrowUpIcon`, `KeyIcon`, `LoadingSpinner`) 및 상수 값들을 정의합니다.
*   **`types.ts`**:
    *   애플리케이션에서 사용되는 주요 데이터 구조에 대한 TypeScript 인터페이스 및 열거형(enum)을 정의합니다. (예: `StockInfo`, `RecommendationAction`, `ActualSimulatedPerformance`).
*   **`index.html`**: 애플리케이션의 진입점 HTML 파일. Tailwind CSS, Chart.js CDN을 로드하고, `index.tsx`를 모듈로 임포트합니다.
*   **`index.tsx`**: React 애플리케이션을 DOM에 마운트하는 최상위 스크립트.
*   **`metadata.json`**: 애플리케이션 메타데이터 (이름, 설명 등).

## 7. API 키 관리

*   **입력 UI**: `App.tsx` 내에 Gemini API 키를 입력하고 저장할 수 있는 UI 섹션이 있습니다. 입력 필드는 비밀번호 타입으로 표시되어 키가 화면에 노출되지 않도록 합니다.
*   **로컬 스토리지**: "저장" 버튼 클릭 시, 입력된 API 키는 브라우저의 로컬 스토리지 (`localStorage`)에 `geminiApiKey`라는 키로 저장됩니다.
*   **상태 표시**: API 키의 상태는 다음과 같이 UI에 표시됩니다:
    *   `API 키가 필요합니다 (노란색)`: 로컬 스토리지나 환경 변수에서 키를 찾을 수 없는 경우.
    *   `API 키 로드됨 (파란색)`: 키가 존재하지만 아직 API 호출을 통해 유효성이 검증되지 않은 경우.
    *   `API 키 활성됨 (초록색)`: API 키가 성공적으로 API 호출에 사용된 경우.
    *   `API 키가 유효하지 않습니다 (빨간색)`: API 호출 시 키가 유효하지 않다는 오류가 반환된 경우.
    *   `API 키 저장 중... (회색)`: 키 저장 작업 진행 중.
*   **우선순위**: 애플리케이션은 다음 순서로 API 키를 사용합니다:
    1.  로컬 스토리지에 저장된 키.
    2.  `process.env.API_KEY` 환경 변수 (로컬 스토리지에 키가 없을 경우).

## 8. 시뮬레이션 로직

*   **데이터 소스**: 시뮬레이션은 `services/yahooFinanceService.ts` 에서 제공하는 과거 주가 데이터(날짜, 시가, 종가)를 사용합니다. **(현재는 모의 데이터)**
*   **일일 AI 신호**: 사용자가 선택한 시뮬레이션 기간 내 각 거래일에 대해, `services/geminiService.ts`의 `getDailyStockSignal` 함수를 호출하여 Gemini API로부터 '매수' 또는 '매도' 신호를 받습니다. API 과부하를 피하기 위해 각 일일 신호 요청 사이에 500ms의 지연이 있습니다.
*   **거래 규칙**:
    *   **진입/청산 가격**: 모든 거래(매수, 매도)는 해당일의 **시가(open price)**에 이루어진다고 가정합니다.
    *   **포지션**: 현재는 '매수 후 보유'(LONG) 또는 '포지션 없음'(NONE) 상태만 지원합니다. 공매도(SHORT)는 구현되어 있지 않습니다.
    *   **매수 신호**: 현재 포지션이 없다면, 가용 자본 전체를 사용하여 해당일 시가에 주식을 매수합니다. 이미 매수 포지션이라면 유지합니다.
    *   **매도 신호**: 현재 매수 포지션을 보유 중이라면, 보유 주식 전체를 해당일 시가에 매도합니다. 포지션이 없다면 관망합니다.
    *   **신호 없음**: AI로부터 명확한 '매수' 또는 '매도' 신호를 받지 못한 경우 (예: "신호 없음" 응답), 현재 포지션을 유지합니다.
*   **평가**: 각 거래일 종료 시점의 포트폴리오 가치는 해당일의 **종가(close price)**를 기준으로 계산됩니다.
*   **결과**: 시뮬레이션 종료 후, 총 시작 자본, 최종 자본, 수익/손실(금액 및 비율), 총 거래 횟수, 그리고 각 거래일의 상세 로그(날짜, 시가, 종가, AI 신호, 당일 행동, 포지션 상태, 보유 주식 수, 포트폴리오 가치)가 제공됩니다.
*   **시각화**: Chart.js를 사용하여 시뮬레이션 기간 동안의 일일 종가 추세선과 실제 거래가 발생한 지점(매수/매도 표시)을 차트로 보여줍니다.

## 9. 오류 처리 및 재시도

*   **API 오류**: `geminiService.ts`는 Gemini API 호출 시 발생할 수 있는 오류(예: API 키 유효하지 않음, 사용량 초과 - 429 오류, 기타 네트워크 문제)를 감지합니다.
    *   API 키 관련 오류 발생 시, 사용자에게 명확한 메시지를 표시하고 API 키 상태를 'INVALID'로 업데이트합니다.
    *   API 사용량 초과(Rate Limit, 429) 오류 시, 최대 3회의 재시도 로직(지수 백오프 방식은 아니지만 점진적 딜레이 증가)이 구현되어 있습니다.
*   **데이터 로딩 오류**: 과거 데이터 로딩 중 문제 발생 시 (예: 모의 데이터 생성 실패 또는 데이터 부족) 관련 오류 메시지를 표시합니다.
*   **UI 피드백**: 로딩 중일 때는 로딩 스피너를, 오류 발생 시에는 `ErrorMessage` 컴포넌트를 통해 사용자에게 상황을 알립니다.

## 10. 제한 사항 및 향후 개선점

*   **실제 과거 데이터 연동**: 현재 `yahooFinanceService.ts`는 모의 데이터를 생성합니다. 실제 금융 데이터 API(예: Yahoo Finance API, Alpha Vantage, IEX Cloud 등)를 연동하여 정확한 과거 데이터를 기반으로 시뮬레이션해야 합니다.
*   **시뮬레이션 기능 확장**:
    *   공매도(Short Selling) 전략 지원.
    *   거래 비용(수수료, 세금) 및 슬리피지(Slippage) 반영.
    *   다양한 자본 관리 및 리스크 관리 전략 옵션 추가.
*   **빌드 시스템 부재**: 현재는 CDN과 ES 모듈을 통해 직접 실행됩니다. Vite, Next.js 또는 Create React App과 같은 빌드 도구를 도입하면 다음과 같은 이점이 있습니다:
    *   코드 최적화(번들링, 최소화).
    *   `process.env`와 같은 환경 변수의 안정적인 사용.
    *   더 나은 개발 환경 및 의존성 관리.
*   **상태 관리**: 애플리케이션 규모가 커지면 Redux, Zustand, Recoil 등 전역 상태 관리 라이브러리 도입을 고려할 수 있습니다.
*   **API 키 보안**: 현재 API 키는 로컬 스토리지에 저장되며, 모든 API 호출은 클라이언트 측에서 직접 이루어집니다. 이는 데모 또는 개인용으로는 편리하지만, 프로덕션 환경에서는 보안에 취약할 수 있습니다. 중요한 애플리케이션의 경우 API 키는 백엔드 서버에서 관리하고, 클라이언트는 백엔드를 통해 API를 호출하는 방식이 권장됩니다.
*   **테스트**: Jest, React Testing Library 등을 사용한 유닛 테스트 및 통합 테스트 코드 작성이 필요합니다.
*   **접근성(A11y)**: ARIA 속성 사용, 키보드 네비게이션 편의성 등 웹 접근성 표준을 지속적으로 개선해야 합니다.
*   **다국어 지원(i18n)**: 현재 한국어로 고정되어 있으나, 향후 다국어 지원을 고려할 수 있습니다.
*   **응답 스트리밍**: Gemini API의 스트리밍 응답 기능을 활용하여 사용자에게 더 빠른 피드백을 제공할 수 있습니다 (특히 긴 분석 이유 텍스트 등).
